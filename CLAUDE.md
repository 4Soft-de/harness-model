# Working in this repository

Operational notes for coding agents. `README.md` covers what the libraries are and how to consume
them; [`docs/index.md`](docs/index.md) covers the architecture. This file covers how to build, test
and change things without stepping on the traps.

Java 21, Maven (use the wrapper `./mvnw`), default branch `develop`.

## Module layout

| Module | Contains |
|---|---|
| `navext` | `navext-xjc-plugin`, `navext-runtime` — the XJC plugin that adds parent/back-reference navigation to the generated models, plus its runtime |
| `kbl` | `kbl-common`, `kbl-v24`, `kbl-v25` — JAXB models generated from the KBL schemas |
| `vec` | `vec-common`, `vec-v113`, `vec-v12x`, `vec-v2x`, `vec-scripting` — JAXB models generated from the VEC schemas |
| `compatibility` | version-to-version migration of VEC documents (`vec11to12`, `vec12to20`) |
| `vec-rdf` | RDF tooling around VEC |
| `kbl2vec` | the KBL→VEC converter — see [`kbl2vec/ARCHITECTURE.md`](kbl2vec/ARCHITECTURE.md) |

`kbl2vec` consumes **`kbl-v25`** (plus `kbl-v24` for reading older files) and **`vec-v2x`**. When you
need to look at a model class, that is almost always the pair you want.

## The model classes are generated — read them under `target/`

The KBL and VEC model classes do **not** exist in `src/`. They are generated by XJC into e.g.:

```
kbl/kbl-v25/target/generated-sources/xjc-kbl25/com/foursoft/harness/kbl/v25/
vec/vec-v2x/target/generated-sources/xjc-vec2x/com/foursoft/harness/vec/v2x/
```

Consequences:

- On a fresh clone these do not exist at all. Generate them first — `./mvnw install -DskipTests`
  (needs network once), or for a single consumer `./mvnw -o -pl kbl2vec -am compile -DskipTests`.
- A naive `find . -name "KblFoo.java"` returns one hit per model version. Filter to the version the
  module you are editing actually uses.
- The **schemas** are the source of truth for cardinalities and are in `src/`:
  `vec/vec-v2x/src/main/resources/vec2/vec_2.2.0-strict.xsd`, and the KBL schemas under `kbl/*/src/`.
  The generated Java cannot tell you whether an element is required — the XSD can. See the
  "Adding a new transformer" checklist in `kbl2vec/ARCHITECTURE.md`.

## Build and test

```bash
./mvnw -o -pl kbl2vec -am compile -DskipTests   # compile one module + its dependencies, offline
./mvnw -o -pl kbl2vec test                      # run one module's tests
./mvnw -o -pl kbl2vec test -Dtest=SomeTest      # run one test class
```

`-o` (offline) works once the dependencies are in the local repository, and is much faster.

## Snapshot tests (`kbl2vec`)

`KblToVecConverterTest` converts four real `.kbl` sample files end to end and compares the serialized
VEC against `kbl2vec/src/test/java/com/foursoft/harness/kbl2vec/__snapshots__/KblToVecConverterTest.snap`,
then validates the result against the VEC schema. Any mapping change shows up as a snapshot diff —
that is intentional, the diff is the review surface.

To regenerate the snapshots:

```bash
./mvnw -o -pl kbl2vec test -Dtest=KblToVecConverterTest -DupdateSnapshot=
```

Note the trailing `=` (empty value means "all snapshots"). Do **not** edit
`src/test/resources/snapshot.properties` to do this, and note that `-Dsnapshot.update-snapshot=all`
looks plausible but is silently ignored.

Always review the regenerated diff before committing. Adding an element shifts the deterministic XML
IDs of everything after it, so a small mapping change legitimately produces a large diff; check that
the *structural* changes are the ones you intended.

## License headers are added by the build — never write them by hand

`license-maven-plugin:update-file-header` is active and bound to `process-sources`. Create new
`.java` files with no header; the next `./mvnw compile` inserts the MIT header. Do not copy the
25-line block from a neighbouring file.

## Conventions

- 4-space indent, no tabs; opening brace on the same line. Otherwise match the surrounding code —
  there is no enforced formatter (see `.github/CONTRIBUTING.md`).
- Commit messages in this repo do not carry a `Co-Authored-By` trailer.
- Branch off `develop` and target PRs at `develop`; PRs are squash-merged.

## Release notes

The notes of a release are embedded by Renovate and Dependabot into the update pull requests of every
consumer, so their format and their wording follow fixed rules. Before drafting or reviewing them,
read [`.claude/skills/release-notes/SKILL.md`](.claude/skills/release-notes/SKILL.md).
